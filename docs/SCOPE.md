# 범위: 지금 할 수 있는 것부터 이상안까지

작성 2026-09-28. 방향은 `docs/DIRECTION.md`, 현업·시장 근거는 `docs/ROI_EVIDENCE.md`, 데이터와 모델 확인 결과는 `docs/HANDOFF.md`(특히 5.4, 7.3).

## 0. 한 줄 요약

**대물보상 담당자가 정비업체 견적과 상대 보험사 과실에 대해 "상대가 받아들일 근거"를 만드는 에이전트.**
- 지금 바로 만들 수 있고 실측 정답으로 채점되는 부분은 **수리비 사정**이다.
- **과실**은 기본과실까지 가능하다. 수정요소는 준비가 더 필요하다.
- 외부 시스템 연동(AOS, 부품 재고, 협회 심의 시스템)은 이상안으로 발표에서만 다룬다.

## 1. 단계 정의

| 단계 | 뜻 | 조건 |
|---|---|---|
| **L1 지금 가능** | 보유 데이터 + 무료 API + 이 PC로 된다 | 추가 비용·다운로드·설치 없음 |
| **L2 준비하면 가능** | 해커톤 안에서 할 수 있지만 준비가 필요하다 | 공개 문서 다운로드, 직접 라벨링, 패키지 설치, Brev 비용(수천~1만 원대), 본선 DGX Spark |
| **L3 이상안** | 실제 서비스라면 필요하지만 우리가 재현할 수 없다 | 보험사 내부 시스템·외부 데이터 연동. 발표의 확장 로드맵 |

## 2. 업무별 정리

### A. 수리비 사정 (정비업체와 협의) — 가장 단단함

| 단계 | 할 수 있는 것 | 근거·정답 |
|---|---|---|
| L1 | ① 사진 파손 방향과 견적 수리 항목 대조 → 사진에 없는 부위 표시 | 파손 사진 라벨, `aihub/parts.py` 매핑 |
| L1 | ② 실제로 자주 깎이는 항목 표시: 도장 부대비용(가열건조비, 수용성 도료, 컬러매칭), 공통시간작업, 브라켓류 | 쏘카 실제 불인정 기록 |
| L1 | ③ 판금·수리 작업시간이 같은 차종·같은 작업 대비 과한지 판단 | 쏘카 실제 인정 공임 분포(6.3만 건) |
| L1 | ④ 사진이 스크래치뿐인데 범퍼를 교환한 건을 **검토 후보**로 표시 | 1,851건(쏘카 341건). 정답이 없어 탐지 후보로만 씀 |
| L1 | ⑤ 항목별 근거를 단 조정 내역서, 정비업체 공문 초안 → 담당자 승인 | Ultra(한국어) |
| L1 평가 | 항목 불인정·감액 재현율·정밀도, 인정액 오차 | **쏘카 실제 손해사정 결과**(9,436건 조정) |
| L2 | 표준약관 경미손상 수리기준 원문을 스킬로 만들어 ④에 약관 근거 인용 | 공개 약관 확보(다운로드 승인 필요) |
| L2 | 국토부 공표 적정 정비요금을 근거로 인용 | 공개 자료 확보 |
| L2 | 사진 판독을 라벨 대신 모델(Omni 이미지 등)로 하고 정확도 측정 | 파손 라벨(손상 4종, 부위 일부) |
| L3 | AOS 연동, 부품 품번 단위 대조, 고품(탈거 부품) 사진 검증 | 보험개발원·보험사 시스템 |
| L3 | 보험개발원 표준작업시간, 부품 재고·단가 실시간 조회 | 비공개 또는 약관상 수집 불가 |
| L3 | 도막 두께·긁힘 깊이 같은 계측값 기반 경미손상 판정 | 현장 계측 장비 |

### B. 과실 협의 (상대 보험사와 협의)

| 단계 | 할 수 있는 것 | 근거·정답 |
|---|---|---|
| L1 | ① 영상 → 사고유형 → 기본과실. 최선의 설정은 Omni + 프레임 8장 + 영어 후보표 + 추론 off | 평가 세트 150건, AI Hub 라벨(= 코드표 기본과실) |
| L1 | ② 근거로 코드표 항목(장소, 진행 방향, 기본과실) 인용 | `accident_codes.csv` |
| L1 | ③ 기본과실까지 담은 협의 문서 초안 | Ultra |
| L1 평가 | 사고유형 top-1/top-3, 기본과실 완전 일치 | AI Hub 라벨 |
| L2 | 과실비율 인정기준 원문(공개 PDF) → 코드별 **도표 번호** 매핑 + **수정요소 목록** 스킬 | 다운로드 승인 필요 |
| L2 | 수정요소 증거 재조사 루프: 해당 구간 프레임을 다시 뽑아 "방향지시등을 켰나" 등을 묻는다 | 정확도 미지수(가장 큰 리스크) |
| L2 | 수정요소 정답 20~30건 직접 라벨링(초안은 Claude, 검수는 사용자) → 소규모 평가 | 사람 시간 |
| L2 | **Cosmos3 Reasoner 직접 실행**(Brev L40S 약 $4~7, 또는 본선 DGX Spark) → Omni와 비교 | 호스팅 API에는 없음 |
| L2 | 다른 모델을 프레임(이미지)으로 시험: Gemma 4(다국어), Llama 3.2 90B Vision 등 | Gemma 4 호스팅은 영상 입력이 꺼져 있음 |
| L2 | AI Hub 제공 DetectoRS(신호등 색 등 객체 9종)로 신호 인식 보완 | GPU 실행 환경 필요 |
| L3 | 상대 보험사와 실제 협의, 협회 심의 프로그램 연동 | 금융보안 전산망 안의 시스템 |
| L3 | 실제 심의 결과 데이터로 "심의까지 갈 가능성" 예측 | 비공개 데이터 |

### C. 이상 징후 (SIU 이관)

| 단계 | 할 수 있는 것 | 근거·정답 |
|---|---|---|
| L1 | 사고유형상 충돌 방향과 사진 파손 방향이 전혀 안 맞는 건 → SIU 이관 메모 | 합성 사고 건(모순 30건, 정답 있음) |
| L1 | 모사 데이터 기반 "충돌유형 × 충돌부위" 참조표를 보조 근거로 사용 | 71958 모사 데이터 487건 |
| L2 | 합성 건에 가상 정비업체 ID를 붙이고 일부에만 과잉 청구 패턴을 심어 공장 단위 탐지 | 정답 자동 생성 |
| L2 | AI 생성 영상 탐지(`ai-synthetic-video-detector`) | 호출 가능 여부 미확인 |
| L3 | 실제 사고이력 DB, 보험사기 네트워크 분석 | 보험사 내부 데이터 |

### D. 대차료·수리 지연

| 단계 | 할 수 있는 것 |
|---|---|
| L1 | 없음. 견적의 입고·출고일로 계산한 수리 기간 중앙값이 1일로 나와 필드 의미가 불분명하다 |
| L2 | 모형 도구("부품 재고 조회")로 데모 장면만 보여준다. 모형임을 명시한다 |
| L3 | 부품 유통망 재고·입고일 API, 렌터카 업체 연동 |

### E. 에이전트 구조 (NemoClaw, 계획 루프)

| 단계 | 할 수 있는 것 |
|---|---|
| L1 | 현재의 고정 파이프라인(`agent/pipeline.py`)을 **플래너 루프**로 바꾼다. Ultra가 도구 호출로 건마다 다른 계획을 세우고, 근거가 부족하면 재조사한다. 기존 `agent/tools/`는 도구로 재사용한다 |
| L1 | 목표를 받아 여러 건을 처리하는 입구: "오늘 배당 건마다 근거 묶음을 만들고, 심의 갈 건은 따로 표시해줘" |
| L2 | NemoClaw 하네스 설치 후 그 위에서 실행(WSL2 실험적 지원 또는 Brev CPU 인스턴스) |
| L3 | 보험사 보상 시스템에 품의서 기안 연동 |

### F. 보안 (OpenShell, 가드레일)

| 단계 | 할 수 있는 것 |
|---|---|
| L1 | OpenShell 정책 YAML 작성: 사건 폴더만 읽기, NVIDIA API만 허용, 외부 발송은 승인 후 |
| L1 | 가드레일 모델 호출로 번호판·얼굴·연락처 출력 차단(safety-guard는 호출 확인됨) |
| L2 | OpenShell 설치 후 실제 차단 로그, 에이전트별 신원·권한 분리, 문서 속 지시문 공격 차단 시연 |
| L3 | 금융보안 전산망 안에서 로컬 NIM(DGX Spark)으로 운영 |

### G. 스킬과 성장

| 단계 | 할 수 있는 것 |
|---|---|

| L1 | 쏘카 조정 이력에서 규칙을 뽑아 "담당자 수정 → 새 스킬" 장면을 재현 |
| L2 | NVIDIA 공식 스킬 설치·사용(`skill-card-generator`, `nemotron-policy-generator` 등. 패키지 설치 승인 필요) |

## 3. 조합안

| 안 | 구성 | 장점 | 한계 |
|---|---|---|---|
| **현실안**(L1만) | 수리비 사정 에이전트 + 기본과실 + 모순 탐지. 플래너 루프, 스킬, 정책 YAML까지 | 지금 바로 시작할 수 있고 **실측 정답으로 채점** | OpenShell·NemoClaw 실제 실행 장면이 없어 기술 심도가 약하다 |
| **권장안**(L1 + 핵심 L2) | 현실안 + OpenShell·NemoClaw 실제 실행 + 약관 경미손상 스킬 + 인정기준 수정요소 스킬(정성) + Cosmos 비교(본선 또는 Brev) | 채점 항목 4개를 고르게 채운다 | 설치 작업과 수정요소 라벨링 시간이 든다 |
| **이상안**(L3) | 보험사 시스템·부품망·협회 심의 연동, 심의 예측, 계측 기반 판정 | 실제 서비스 모습 | 재현 불가. 발표 로드맵 슬라이드로만 |

**권장:** 권장안을 목표로 하되, 현실안을 먼저 끝까지 돌아가게 만든다.

## 4. 지금 정해야 할 것

1. 주인공: 수리비 사정(데이터 강함)이냐 과실 협의(현업 마찰 큼, 인식 리스크 큼)냐. 과실 15건 소표본 결과로 정하는 것을 제안한다.
2. 인정기준 원문 PDF와 표준약관 다운로드 여부.
3. NemoClaw·OpenShell 실행 환경: WSL2(무료, 실험적) 또는 Brev(유료).
4. Cosmos 직접 실행: Brev(약 6천~1만 원) 또는 본선까지 대기.

## 5. 바로 할 수 있는 다음 작업 (무료)

1. 과실 15건 소표본: Omni + 프레임 + 영어 후보표(호출 최대 25회, 약 10만 토큰, 0원).
2. Gemma 4 이미지 입력 1~2회 시험(0원).
3. 고정 파이프라인을 플래너 루프로 바꾸는 설계(비용 없음).

## 6. 미착수 목록: 영상 분석 이후 과실 판단까지 (2026-09-28 코드 점검)

지금 파이프라인(`agent/pipeline.py`)은 **영상 → 사고유형 코드 → 코드표 기본과실**에서 끝난다. 사정서에는 "수정요소: 담당자 확인 필요" 한 줄만 나온다. 영상 모델을 DeepSeek나 VSS로 바꿔도 아래가 비어 있다.

**① 영상 분석** (`agent/backends/nim.py`)
| 항목 | 현황 |
|---|---|
| DeepSeek v4.1 flash 연결 | 스트리밍 응답이 없어 호스팅 게이트웨이 300초 제한에 걸린다(504, HANDOFF 5.4). 추론 설정은 Omni 기준뿐 |
| "해당 도표 없음 → 사람 이관" | 모델이 무조건 top-3를 고르고, 없으면 `search_fault_table`이 예외로 멈춘다. F003(앞차 후진)처럼 코드표에 없는 사고를 걸러낼 길이 없다 |
| 확신도 | `VideoFinding`에 확신도가 없어 "애매하면 사람 확인" 분기를 만들 수 없다 |
| 프레임 선택 | 10초를 균등 8장. 충돌 전후를 촘촘히 다시 보는 단계가 없다 |
| 신호 인식 보완 | DetectoRS 하이브리드(HANDOFF 11절) 미착수 |
| 스킬화 | 영상 분석을 SKILL.md 스킬로 감싸고 당일 `vss-ask-video`로 바꿀 수 있는 구조(HANDOFF 5.2.1) 미착수 |

**② 과실 판단** (`agent/tools/fault.py`)
| 항목 | 현황 |
|---|---|
| 손해보험협회 인정기준 원문 | 미확보. 지금 표는 AI Hub 설명서 코드표라 도표 번호(차XX-X)·수정요소·판례가 없다 |
| 인정기준 검색(RAG) | 원문이 없어 미착수. 한국어 임베딩 `nemotron-3-embed-1b`는 무료 API로 호출 가능 |
| 수정요소 재조사 루프 | 코드 없음. 도표별 수정요소마다 영상 구간을 다시 묻고 근거 시각을 남기는 도구 필요 |
| 수정요소 정답 | AI Hub 필드 채움률 0% → 20~30건 직접 라벨링 필요 |

**③ 진술 대조**
| 항목 | 현황 |
|---|---|
| 당사자 진술 합성 | `ClaimBundle.statement` 칸만 있고 항상 빈 값. 영상과 일치/불일치 진술 합성 미착수(`data-designer` 후보) |
